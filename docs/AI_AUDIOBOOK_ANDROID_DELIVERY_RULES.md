# AI 多角色听书 Android 交付补充规则

本文件是 AI 多角色听书一期实现对现有仓库规范的项目级补充，不替代通用发布、日志、测试和安全规则。

## 1. 本阶段交付口径

- 本阶段以 Mac 上构建测试包并在 Android 模拟器或 Android 设备完成验收为准。
- 测试包固定为 `io.legado.miss.app.debug`。
- `assembleAppDebug` 可以作为过程构建和模拟器安装来源；它不等价于正式发布 APK。
- Windows 发布脚本、正式签名、正式服务器部署和 Windows 服务联调不阻断本阶段 Android debug 验收。
- 本阶段不得声称正式发布完成，也不得把测试包冒充正式包。

## 2. 不得跳过的安全与数据规则

- NovelAudio URL 和 Token 必须保持不可变配对；Token 只能进入独立 Android Keystore 加密存储。
- 日志、异常、Room 角色 JSON、文件名、缓存键和更新日志不得包含 Token、正文或完整 URL 凭据。
- Room 新表必须使用从 `AppDatabase.kt` 当前版本递增的显式 migration；迁移测试必须证明旧书、旧人物、旧朗读缓存仍在。
- `READY` 必须同时满足计划、正文、全部音频文件、SHA-256 和可解码性。
- 飞行模式、进程恢复和启动恢复不得为缺失音频自动发起书源、分析、声库或 TTS 请求。
- 音频失败不得用空文件、静音文件或“播放成功”状态伪装。
- Gson wire model 必须保留泛型签名，所有服务器响应 DTO 使用 `@Keep`。

## 3. 测试与证据

- 每个生产代码变更必须有对应的 JVM、Room 或 AndroidTest 更新；修复必须先有失败复现。
- 先运行定向测试，再运行 `:app:testAppDebugUnitTest`；失败时不得把文档状态写成完成。
- Android 验收至少记录配置保存/清除、主动播放授权、当前章与跨章、固定三章窗口、手动 PINNED、重启恢复、飞行模式播放、缺段不 READY 和普通 TTS/HTTP TTS 回归。
- 缺失的统一 runner、测试配对、Gson 和主题门禁按当前仓库补建并写失败自检；提交/交付前必须执行适用检查，缺失或失败不得伪报通过。正式发布专属检查不纳入本阶段 debug 完成条件。
- 真实服务未部署时，Mock 只能证明协议、状态和解码链路，不能证明真人音质或正式服务联调。

## 4. UI 开工卡 K1

涉及 NovelAudio 设置、人物或下载页面时，编码前必须在任务记录中完成：

1. 查明既有设置项、主题 token 和同语义组件；
2. 复用既有双栈实现，不新增未经登记的硬编码颜色；
3. 覆盖默认、自定义主题色、主题包和夜间四态；
4. 为新增入口列出对应 JVM/AndroidTest。

K1 必须记录实际查阅的组件与 token。K2 由补建后的 runner 执行，K3 保留四态设备证据，K4 把发现的问题加入门禁自检；不能用人工勾选替代可执行门禁。

## 5. 交付边界

- 本阶段可以交付 Android debug 可用链路。
- release 签名、Windows 发布脚本、正式服务器联调、正式音质验收另行记录。
- 不因本阶段交付自动增加云调用次数，不自动切换模型，不自动切换到付费额度。
