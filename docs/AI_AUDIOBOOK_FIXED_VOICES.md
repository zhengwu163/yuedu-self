# 固定角色声音

VoiceDesign 的描述决定声音风格，不保证每次生成都是同一位说话人。整章逐段调用 VoiceDesign，可能在同一个 `voiceAssetId` 下出现不同的实际声音。

本机听书采用以下流程：

1. 从一次 VoiceDesign 生成中选定旁白、男声、女声参考样本。样本必须由用户试听确认；不修改模型权重。
2. 将每份样本转换成 24000 Hz、单声道、PCM16 WAV，保存在服务根内的新版本目录。原样本和已有参考录音保留。
3. 新建音色目录，保留原音色的 ID、性别、特征和 `narrator` 标记，将 `kind` 改为 `base`，填写根目录内的相对 `referenceAudio` 和与录音对应的 `referenceText`，去掉 `prompt`。参考文本仅存在本机私有配置，禁止提交。
4. 新建运行配置：9B 文本模型与现有 TTS Base 模型组合，能力声明为 `chapter-analysis`、`speech-synthesis`、`voice-clone`、`zh-CN`。本机配置名为 `qwen35-9b-fixedvoices`，原来的两个配置保留。
5. 停止服务且确认租约已释放后，切换 `activeProfile` 和 `voiceCatalog`。JSON 使用无 BOM 的 UTF-8。先执行 `check-models.ps1`，再启动、跑真实 HTTP 验证。

Base 适配器在同一 Worker 中按参考录音、参考文本和克隆模式缓存 `create_voice_clone_prompt` 的结果。每段使用同一份 `voice_clone_prompt`；不同角色不共用参考特征。Worker 卸载时清空缓存，下一次仍从相同的固定参考录音构建。预览和正文使用同一条配音路径。

手机端沿用分析模型写入角色时使用的作品标识。无作者 TXT 的 AI 听书标识与普通多角色朗读的历史标识不同，播放面板及其角色管理入口必须选择对应标识，且列表缓存要随角色变化失效。普通朗读和 HTTP TTS 的历史角色存储不迁移。

已经生成的旧章节不会自动变成新的声音。首次切换后，应为当前章节创建新的固定下载计划并确认音频的 `X-TTS-Profile` 对应固定音色配置；保留旧音频，不能把旧缓存的播放当作修复验收。后续变更参考音色还需要明确版本化和重新生成，不能覆盖旧参考文件。

验收需要同一声音的多段样本，确认参考绑定与实际声音都稳定；仅看音色 ID 相同不足以证明音质通过。最终人耳试听是必需的一步。
