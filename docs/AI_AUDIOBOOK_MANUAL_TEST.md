# 本地手工测试环境

这套工具用于在功能开发就绪后，让测试者在 Android 模拟器或手机上亲手操作应用、听声音并记录问题。当前交付范围是环境准备和基础连通性检查，不代表多角色听书功能已通过验收。

## 已准备的内容

- Android 模拟器 `legado_test`，使用应用测试包。
- 本机语音服务：使用 Mac 系统语音，提供 9 个音色配置，无需真实模型密钥或付费合成服务。
- 浏览器控制台：显示本服务的合成请求记录，并可模拟慢响应、超时、鉴权失败、限流、服务器错误和空音频。
- 测试书生成器：30 章多人对话、同名不同作者、同书副本，以及长章、极短章、符号、引号和场景称谓等文本。
- 问题采集：保存设备截图、日志、语音请求记录及环境信息。

## 使用方式

脚本针对 Apple Silicon Mac 配置，依赖 Java、Python 3、Android command-line tools 和 macOS 系统语音；安装 ffmpeg 时输出 MP3，否则回退到 WAV。默认 SDK 路径为 Homebrew 路径，可用 `ANDROID_HOME` 指定。运行时只连接一台测试设备或模拟器。

在项目根目录执行：

```bash
# 首次准备 SDK、模拟器和测试书；本机此前已完成
bash scripts/manual-test/setup.sh

# 启动环境，覆盖安装已有的最新测试包，放入测试书
bash scripts/manual-test/start.sh

# 弹出引擎导入确认框；在设备上确认，并在朗读设置中选择本机引擎
bash scripts/manual-test/import-tts.sh
```

测试书位于设备的「下载/legado-test」，需在应用里手动导入。语音控制台地址为 `http://127.0.0.1:8765/admin`。

```bash
# 发现问题时记录现场
bash scripts/manual-test/collect.sh "描述刚才的操作和异常"

# 结束测试；会关闭 adb 可见的模拟器和脚本记录的本机语音服务
bash scripts/manual-test/stop.sh
```

`install.sh --fresh` 会卸载应用并清空书架与设置，日常使用默认的覆盖安装即可。`--build` 仅用于本机过程验证；正式交付包仍应遵循项目打包流程。

截图和日志保存到 `output/manual-test/bugs/`，可能含书籍文本及设备信息，分享前应检查。测试书和运行产物不进入 Git，测试书可由生成器重建。

## 验证范围与后续安排

准备阶段已做过应用到本机语音服务的单次合成连通性检查，随后按要求恢复了应用初始状态。连续播放及多角色链路没有完成验收。

等相应功能开发就绪后，再依次人工检查：导入与打开书籍、角色识别与音色分配、播放与切章、下载与断网播放、异常提示与恢复。详细的逐项操作和预期结果应按实际可用版本补充。

控制台计数只统计本服务已完成处理的合成请求；计数为零不能单独证明应用完全没有网络活动，也不能排除仍在等待中的请求。离线能力需要结合断网操作、实际播放和日志验证。Mac 语音只能验证流程，不能代表真实 AI 模型的角色识别能力或最终音质。

## 工具自测

```bash
python3 -B -m unittest discover -s scripts/manual-test -p 'test_*.py' -v
```

这些测试检查 Shell 语法、引擎配置、音色目录和测试书结构，不操作 Android 应用。
