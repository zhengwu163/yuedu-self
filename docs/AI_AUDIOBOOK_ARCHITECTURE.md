# AI 多角色听书：一期目标架构

本文是实现契约，不是已完成声明。当前源码事实见
[现状审计](../CURRENT_ARCHITECTURE.md)，实际完成度见[进度](AI_AUDIOBOOK_PROGRESS.md)。

## 产品边界

普通读者在现有阅读器打开 AI 多角色朗读即可持续收听。旁白独立配音，
人物自动识别、首次选音后保持稳定；低置信度归因降级，不要求逐句审核或逐章确认。

一期包括完整离线音频：

- 当前章优先，默认自动准备后续 3 个完整章节，可选择 2 章；播放推进后滚动补充。
- 主动下载后续 10/20 章或自定义范围；不默认分析/合成全书。
- 正文、注释、播放计划及全部音频共同保存；标为“已下载”的章节离线重启后仍能播放。
- 提供进度、暂停、继续、取消、按书清理及删除已听章节；继续只补缺失部分。
- 手动下载属于用户保留内容，滚动清理不能删除；空间不足暂停新生成并说明原因。
- 支持仅 Wi-Fi 批量下载；首次启用告知正文外传、模型/TTS 服务额度及本地空间消耗。

一期不包含 RAG、知识图谱、逐句情绪、二轮 LLM 审核、BGM/SFX、专业时间轴、
MP3/M4B 出版导出、声音克隆或模型训练。

## 总体链路

```text
现有正文获取/本地书
  → ChapterTextSnapshot（唯一文本与坐标）
  → 本地 TextUnit 切分
  → ChapterDirector（章节级/长章分块注释）
  → CharacterRegistry + VoiceBinding
  → 共享 SpeechPlan / AudioSegment
       ├─ 当前播放 → 既有 Service / Media3 / 系统 TTS
       ├─ 后续 2–3 章预生成
       └─ 用户范围下载
                  ↓
       同一个合成器、文件缓存与章节 manifest
```

轻量领域对象放在 `help/readaloud/` 下；Room 沿用 `data/entities`、`data/dao`。
保留既有 Service 生命周期、SpeechRoute、HTTP/JS Provider 和 Media3；
不引入新 DI 框架或另一套播放器。后台工作复用 Service/协程，增加持久任务状态。

## 身份与文本不变量

| 对象 | 身份/作用域 | 不变量 |
|---|---|---|
| 逻辑作品 | 标准化书名＋作者的 workKey | 同作品不同书源共享人物、aliases、音色；不同作品隔离 |
| 物理章节 | bookUrl＋chapterUrl＋index＋contentHash | 章节索引相同不意味着正文相同 |
| ChapterTextSnapshot | 物理章节＋文本处理版本 | 不可变正文、hash、段落起始位置；正文不得由 LLM 重写 |
| TextUnit | snapshot 身份＋切分版本＋绝对范围 | offset 使用 Kotlin UTF-16 `[start,end)`，不切断代理对 |
| Character | workKey＋稳定 characterId | 改名不改 ID；外部 ID 必须属于当前作品 |
| VoiceBinding | workKey＋subjectType＋subjectId | NARRATOR 与 CHARACTER 分离，声音变化显式增加 revision |
| AudioSegment | plan 版本＋有序 unit/range＋实际合成参数 | 合成文本由本地快照截取，保持原顺序 |

缺失作者时，不凭同名自动共享新人物数据；新功能使用物理书籍回退身份。
历史 title-only 数据先保留，迁移必须有数据保留和冲突测试，不批量猜测所属作品。

快照生成只在入口执行一次现有可见文本处理，保存处理后的正文和版本；
分析、面板、播放、离线计划都读取同一对象。相对原始章节的清理映射由快照适配层维护。
空白可不发给 TTS，但必须保留其范围和覆盖关系；所有可朗读字符恰好覆盖一次。
超长 unit 在本地按标点/Unicode 边界再拆分，不让 LLM 决定文本边界。

## ChapterDirector 与自动化边界

输入为快照、目标 TextUnit、当前作品角色/稳定 aliases、上块已确认 assignments
和末尾有限原文上下文。正常章节一个请求；长章按本地 unit 分块，
上下文和输出数量均有硬上限，不能通过 full 模式绕过限制。

输出仅包含 unitId → speaker 的注释、新人物建议和稳定 alias 更新建议。
人物描述只保留选音所需的小量信息，不生成改写剧本，不返回音频路径或执行命令。

硬校验由应用完成：

1. unitId 必须位于本次请求集合，不允许重复冲突覆盖或未知 ID。
2. characterId 必须属于当前 workKey；否则归入 UNKNOWN。
3. 新人物建议先经 Registry 规范化、去重、分配稳定 ID，再写 assignments。
4. “师父、哥哥、老师、他”等场景称谓只在本次上下文中解析，不默认成为永久 alias。
5. 缺失、格式错误和低置信度项使用本地旁白/未知声音兜底；原文保持不变。
6. 块按顺序提交人物决议后再分析下一块，同一作品的 Registry 更新串行事务化。
7. 正文视为不可信数据；正文内指令不能修改 Provider、密钥、文件路径或用户设置。

初始工程预算：AI 请求最长 45 秒，最多额外重试一次；可恢复的 429/5xx/网络失败
带退避，认证/配置错误不循环重试。当前播放超过等待预算先使用完整本地降级计划；
当前已开始的播放计划冻结，迟到结果只影响后续尚未开始的计划。
长章使用请求字数上限和最大块数双限，超预算部分降级，避免整章无限等待。
这些是待测初值，不是性能达标报告。

## 人物与声音

复用 `BookCharacter` 主键及现有人物页；新增稳定 alias、独立 VoiceBinding 和合并记录。
Registry 负责所有角色写入，LLM 不直接调用 DAO。

- 首次自动选音依据 Provider 可用音色、性别/年龄等可靠特征；
  无明确特征时用稳定散列和有序候选列表，不能每次随机。
- 自动绑定默认锁定；切换 LLM 模型不变更绑定。
- TTS 模型改变时校验原 voiceId 是否兼容；兼容则沿用，
  不兼容时使用确定性 fallback，并保留原绑定与提示，不偷偷重选所有角色。
- narrator 使用独立绑定；空 voiceId 必须恢复目标默认声，不能沿用上一人物 Voice。
- 用户可试听、换声、改名、看 aliases、合并人物；高级入口可撤销合并。
- 合并保存原 ID、alias/绑定归属及 revision；撤销仅恢复该次操作影响，
  遇到后续人工修改冲突时保留后续修改，不盲目回滚。

## 共享计划、合成与降级

同 speaker、同实际声音参数、相邻文本范围合并为 AudioSegment。
合并受 Provider 的字符/字节限制约束；超限在本地标点处拆分并回写范围映射。
跳转定位用 unit/range → segment 映射，不以 LLM 返回文字计算偏移。

播放与下载共用同一计划和合成实现。HTTP/JS Provider 暴露持久音频能力、
最大长度、返回格式和 model 标识；系统 TTS 只有实际 `synthesizeToFile` 成功并验证
文件后才可记入离线完成。不支持落盘的引擎不能显示“可离线下载”。

TTS 单段超时和重试有界：初始超时 30 秒、额外重试最多一次，
接着使用用户允许的本地/默认 fallback。取消异常向上传递，不作为失败重试。
全部声音失败时明确提示并允许继续/跳过，记录缺段，不能静音冒充完整内容。
当前缓冲可播放时继续播放，后台单段错误不能永久占住队列。

缓存键使用带长度前缀的字段编码再 SHA-256，包含：
键版本、workKey、物理章节、contentHash、unit/range、speakerId、
binding revision、Provider 配置 revision、实际 voiceId、TTS modelId、
合成 speed/pitch/format/sampleRate。纯播放器倍速不改变合成文件键。
API Key 不进入文件名/日志，也不直接参与散列；凭据轮换不无故重生音频。

## 离线 manifest 与任务恢复

持久内容使用应用私有持久文件目录，临时流缓存仍可使用既有 cacheDir。
正文快照、计划和 manifest 与实际文件关联；manifest 保存版本、章节显示信息、
片段顺序、unit/range、缓存键、实际声音、字节数、校验和与完成状态。
离线打开 manifest 必须在正文重新请求、LLM、voice catalog 请求之前命中。

章节状态为 `QUEUED → PREPARING → GENERATING → VERIFYING → READY`；
可转为 `PAUSED`、`WAITING_NETWORK`、`WAITING_SPACE`、`PARTIAL`、`FAILED`、`CANCELLED`。
READY 必须同时满足：

- 本地正文及计划可读、版本匹配、所有可朗读范围完整覆盖；
- 计划中的每一段都有可解码、非占位的完整音频；
- 文件大小/校验和匹配，临时文件不计数；
- 元数据与文件提交完成。使用 fallback 生成真实语音可算完整，但需记录实际声音。

文件先写同目录临时文件，关闭、校验后原子 rename；最后 Room 事务标记片段 READY。
文件系统与数据库不是同一事务：启动恢复需修复“文件已提交、DB 未更新”和
“DB 已完成、文件缺失/损坏”两种状态。后者降为 PARTIAL，并只重生缺失段。

任务持久化请求范围、保留策略、计划版本、进度、重试次数与 generation。
重启后只重新排队仍获授权且未暂停/取消的任务；旧 worker 的提交必须匹配 generation。
暂停保留完整段，取消停止未完成工作且不擅自删除已下载内容。
应用被系统强停时不能承诺继续生成；重开应用或显式恢复时重建队列。
离线启动仅执行本地文件校验、位置恢复和缺段标记；需要远程资源的任务保持
WAITING_NETWORK，fallback 也不得隐式联网。补段必须等网络策略和用户授权同时允许，
不能因为恢复队列而绕过离线播放禁网规则。

调度优先级：当前播放缺段 > 最近待播章 > 滚动窗口 > 手动范围任务。
初始全局合成并发上限 2，同时尊重 Provider 更低限额；低优先级任务在片段边界让出。
相同片段使用单一在途任务；取消某个消费者不能取消其他仍需要该段的消费者。

保留策略：

- AUTO：只维持用户设定的后续 2/3 章窗口及正在播放的章，可按容量回收已听内容。
- PINNED：用户主动下载，直到用户删除；自动任务升级为 PINNED 时不重复合成。
- 当前播放租约保护正在读的文件；清理与生成串行更新引用，防止边播边删。
- 空间不足暂停生成，保留已有下载；不可通过删除 PINNED 内容静默腾空间。
- 修改音色后新计划独立生成，旧 PINNED 版本保持可离线听；
  只有用户要求更新且新版本完整，才替换旧版本。

## 隐私、配置与操作边界

| 项目 | 来源/保存 | 约束 |
|---|---|---|
| LLM endpoint / model | 现有模型配置 UI | OpenAI-compatible；不内置真实凭据 |
| API Key | 用户输入 → Keystore 加密值 | 配置 JSON 只存引用；日志、备份、导出排除明文 |
| TTS Provider / voice | 现有 HttpTTS / JS / 系统配置 | 新音色选择要验证兼容性；离线播放不必联网刷新目录 |
| 正文与音频 | 本地书/用户配置书源 | 首次云处理告知发送内容及服务商；应用私有存储 |
| 自动缓存范围 | 2/3 章设置 | 默认 3，不触发全书请求 |
| 手动下载范围 | 用户本次明确操作 | 仅 Wi-Fi、暂停/取消、额度告知及空间检查 |

API Key 从旧 JSON 迁移时，先加密写入并回读验证，再去掉旧明文；失败不能静默丢失配置。
Keystore 丢失/恢复失败时要求重新配置，不回退明文保存。
Provider 请求日志仅记录阶段、耗时、状态码及不可逆任务标识，不记录正文、响应正文或密钥。
不新增邮件、公共网页、SEO 或服务端定时任务。
